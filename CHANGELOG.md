## [Unreleased]

### Added

- **Explore completion now prints the artifact path and clear next commands for research or ad-hoc work.**

- **README phase-transparency table names `COVERAGE_INCOMPLETE` as the `review pre` fail-closed token.** The review row keeps its comments-only default and not-a-merge-gate wording.

- **Optional `product` pack is back for greenfield scope tracking.** `deviate setup --packs product` installs `/deviate-flows`, `/deviate-architecture`, and `/deviate-release`, which author standalone planning artifacts under `specs/_product/` (flow catalog + index, cross-epic architecture + domain model, release plan). The pack never gates execution, writes no ledger, and defines no `flow_refs` contract — `FLOW-NN` IDs are prose anchors within product artifacts only, and no Macro/Meso/Micro phase reads `specs/_product/`. Constitution 0.11.0 records the optional layer. Pinned by `tests/test_product_pack.py`.
- **Setup on a TTY picks optional packs with a checkbox multi-select.** `deviate setup` with omitted `--packs` shows one optional pack per row where Space toggles and Enter confirms instead of a comma-separated prompt (AC-PLAN-002).

### Fixed

- **`deviate merge --delete-branch` no longer hides unexpected remote-cleanup errors.** Best-effort handling now covers only operating-system failures while local cleanup still continues after expected remote command failures.

- **Fresh `deviate micro run` (and each new TDD cycle) resets leftover TRAIN counters.** `_run_tdd_cycle_impl` calls `_reset_tdd_retry_budget` once at cycle entry, zeroing only `green_attempts` / `red_attempts`. Leftover TRAIN 3/3 in gitignored `.deviate/session.json` no longer blocks a retry the operator thinks is fresh after `git reset` or a new `micro run` / `--all` task. `train_feedback`, `red_commit_sha`, and `pending_judge_action` stay so JUDGE notes are still injected. Increment still happens at each GREEN start in the same invocation; three GREENs in one cycle still escalate. No new flag. Pinned by `tests/test_micro/test_two_counter_retry.py`.

- **COMPLETED after a clean JUDGE `COMPLIANCE_PASS` no longer rematches frozen `test_quote` / `impl_quote` against post-REFACTOR HEAD (GH-191 leftover).** `_require_tdd_completed_evidence` checks this-task AC token coverage and that a named `test_path` exists on disk. It does not re-run `evaluate_judge_evidence(..., use_head=True)` exact-substring matching, so REFACTOR / `_run_format_cmd` may edit cited files (indent, format, `impl_path` move such as `root.html.heex` → `layouts/`) and the cycle still writes COMPLETED. Quotes persist on the COMPLETED row as historical. Empty evidence, a required this-task token with no evidence row, or a named `test_path` absent on disk still raise `COMPLETED_EVIDENCE_MISSING`. Pass is pass (GH-185); `revert_green` is not restored. Pinned by `tests/test_micro/test_completed_evidence.py::TestCompletedAfterRefactorQuoteDrift`. ([#191](https://github.com/wernerbisschoff/deviatdd/issues/191))

- **`deviate micro run` no longer claims a mid-flight JUDGE/REFACTOR/YELLOW task is already completed (GH-193).** `_run_single` prints `TASK_ALREADY_DONE` and exits 0 only when the latest ledger status is `COMPLETED`. After an interrupt or fail-close (COMPLETED_EVIDENCE_MISSING) the session cache can reset to `current_phase: "IDLE"` while `tasks.jsonl` is still `JUDGE` with no COMPLETED row — that is mid-flight: JUDGE re-runs judge, REFACTOR continues refactor, YELLOW continues the post-RED cycle. True COMPLETED + IDLE still no-ops (GH-148 / `skip_refactor` already-exists stays complete). Pinned by `tests/test_micro/test_run.py::TestSessionResume`. ([#193](https://github.com/wernerbisschoff/deviatdd/issues/193))

- **`resolve_task_ac_tokens` no longer treats Rationale forward-references as this-task AC tokens (GH-191).** Card fallback still prefers non-empty `acceptance_criteria` `criterion_id`s, then `**Acceptance Criteria**` lines on the `tasks.md` card. `**Rationale**`, `**Details**`, `**Type**`, `**Files**`, and other non-AC sections are not scraped for `AC-PLAN-NNN` — TSK-002-01 naming `AC-PLAN-002` in rationale does not require that token. Unstructured cards with no labeled sections still yield their body tokens. COMPLETED still fail-closes when the persisted bundle does not cover the resolved this-task set or a named `test_path` is absent; it does not rematch JUDGE quotes against HEAD after a clean pass. Pinned by `tests/test_core/test_judge_evidence.py::TestResolveTaskAcTokens` and `tests/test_micro/test_completed_evidence.py::TestRationaleForwardRefDoesNotBlockComplete`. ([#191](https://github.com/wernerbisschoff/deviatdd/issues/191))

- **`deviate specify` honors `--issue` when the positional issue ID is omitted.** Bare `specify` ignored `--issue` and ran BACKLOG discovery, whose local-worktree guard always skips the already-claimed issues `--second-worktree` targets — `specify --second-worktree --issue <id>` could never claim and exited `NO_CLAIMABLE_ISSUES`. `--issue` now resolves the issue directly; discovery still runs when both are omitted. Also fixes the `NO_CLAIMABLE_ISSUES` message losing its second argument, which rendered as `no unblocked BACKLOG issue  available`. Pinned by `tests/test_meso/test_second_worktree.py::TestSecondWorktreeCliFlag::test_specify_second_worktree_honors_issue_option`.

### Changed

- **TDD tasks are stamped `unit` | `integration` | `e2e`.** Tasks / `/deviate-tasks` no longer emit `Sociable_Unit` / `Solitary_Unit` as runner values. Sociable vs solitary stays a RED style rule (`prefer-sociable`, `mock-only-externals`) inside unit tests and must still run with the DB down under `mise unit`. One TDD task = one layer = one RED; GREEN cannot edit tests and shares the same resolved verification command. RED writes only the stamped layer. The runner and `red pre` / `green pre` resolve the layer and inject `test_strategy`, `test_write_dir`, and `test_command` (`mise unit` / `mise integration` / `mise e2e`) — the agent must not infer the layer from `tasks.md`. The runner may still run cheaper rungs after an integration/e2e RED. An integration-stamped task with no integ suite fails loud (`VERIFICATION_UNRESOLVED`) at pre — it does not fall back to `mise test`. Closing sweep: user-facing + e2e exists → `[E2E]` Verification_Batch with the full existing ladder; else if integ exists → `[VERIFY]` unit-if-exists + integ; else no extra sweep. Never emit empty e2e files; never require integ to be set up. Pinned by `tests/test_cli/test_mise_verification.py`, `tests/test_meso/test_auto_prompt_templates.py`, and `tests/test_core/test_tasks_ledger.py`.

- **`deviate init` scaffolds the named mise tasks RED/GREEN resolve.** Fresh `mise.toml` always defines `unit`, `integration` (`mise integration`), and `doctor` (language-specific commands; no `|| true` on `unit`). Empty stub dirs are created at `tests/unit` + `tests/integration` (Elixir: `test/` stays unit; add `test/integration`) so RED knows where to write. `e2e` is added only when `tests/e2e`, `e2e/`, or `test/e2e` already exists. Empty `integration` treats pytest exit 5 (no tests collected) as success; assertion failures still fail. The runner still accepts `integ` as an alias when a repo already defines that name; init writes `integration`. `pre-push` depends on `unit` only. An existing `mise.toml` is merged: missing `unit` / `integration` / `doctor` are inserted; existing commands, tool pins, and layer folders are left untouched. Pinned by `tests/test_cli/test_init_mise.py`.

### Removed

- **Product layer is gone.** `/deviate-flows`, `/deviate-architecture`, `/deviate-release`, the optional `product` pack, `deviate flows sync`, `deviate inspect flows coverage`, `specs/_product/`, `flow_refs`, and the flow ledger API (`FlowRecord`, `seed_flow_ledger`, …) are deleted — not optional, not tombstoned. Three layers remain: Macro, Meso, Micro. Shard still writes User Stories + ATDD on the issue; RED encodes those scenarios as failing tests. GREEN still cannot edit tests. Historical `issues.jsonl` rows that carry `flow_refs` still parse (the field is ignored). Constitution 0.10.0 records the removal; 0.6.0 / 0.7.0 stay as history.

### Added

Writing either file before the reset is forbidden — the reset would rewind GREEN's JSONL. Resume still uses session / `start_phase`. Pinned by `tests/test_micro/test_judge_feedback_persist.py`.

- **Discarded-commit index on JUDGE reject.** Each rollback writes `head_sha` (HEAD before reset), `reset_to` (blast-radius SHA), and `recovery_ref` (`tmp/deviate-agent-work/<task>/attempt-<N>`, empty when HEAD already equaled the boundary) onto both `.verdicts.jsonl` and the post-reset `tasks.jsonl` row so `git show <head_sha>` / `git switch <recovery_ref>` is greppable. `_preserve_agent_work` stays the object-keepalive; no stash. Pinned by `tests/test_micro/test_judge_feedback_persist.py`.

- **Manual `deviate judge post` confirms before revert so the operator can see the failing tree.** On coerced `revert_green` / `revert_red`, the command prints a planned `head_sha` / `reset_to` / `recovery_ref` preview and waits: TTY `typer.confirm`; non-TTY exits `JUDGE_REVERT_CONFIRM_REQUIRED` with no reset. `--yes` / `--revert` skip the prompt. After reset, the printed and logged index is `_execute_rollback`'s `_RollbackTrace` (not a parallel attempt-1 planner), written on the reject `.verdicts.jsonl` row and the post-reset `tasks.jsonl` row. Inspect with `git switch <recovery_ref>` (not `git stash`). Auto `_run_judge_phase` / `_apply_judge_verdict(..., assume_yes=True)` still reverts immediately. Pinned by `tests/test_micro/test_judge.py::TestJudgePostRevertConfirm`.

- **Per-task JUDGE verdicts JSONL for cycle postmortem.** After a DeviaTDD cycle, `.deviate/logs/<issue>/<task>.verdicts.jsonl` records why JUDGE passed or failed RED/GREEN without grepping a run transcript. `_apply_judge_verdict` appends one JSON object per JUDGE application (pass and reject) so auto and `judge post` share it: `ts`, `task_id`, `issue_id`, `verdict`, `next_action` (after coerce / GH-149 / GH-158), `next_action_raw`, `coerced`, `blast` (`red` / `green` / `none`), `feedback`, `feedback_source`, `violations`, `test_integrity`, `failure_kind`, `streak` (consecutive same-blast rejects), `loop` (`true` when streak >= 2). Run/task transcripts stay scannable: `INVOKE_AGENT` is task/phase/backend/model only (no prompt body); `AGENT_RESULT` is status/verdict/next_action (no full manifest JSON); verbatim stdout and the prompt live in `.deviate/logs/<issue>/<task>.raw/<phase>-<n>.log`. `[log].agent_reasons` in `.deviate/config.toml` defaults to `false` and is not written by setup — when `true`, assembled RED/JUDGE prompts ask for a one-line handover `rationale`. Pre/post/runner logging never checks the flag. Local file only — no dashboard, no `inspect postmortem`, no upload. Pinned by `tests/test_micro/test_judge_verdicts.py`.

- **Scripted TDD-cycle driver replays wild JUDGE/GREEN/RED handovers on both auto and manual paths.** `tests/helpers/cycle_driver.py` seeds a tmp repo + PENDING task + `session.json`, then runs an ordered list of `{phase, handover YAML, files}` steps. Auto patches only `_invoke_agent` so `_run_*_phase` and `_apply_judge_verdict` stay real; manual invokes `deviate <phase> pre` → scripted files → `deviate <phase> post`. Cycle regressions go in those fixtures, not new coerce branches only. No live LLM. Existing GH-158/148 unit tests stay.

### Fixed

- **JUDGE no longer crashes when the GREEN diff includes binary or non-UTF-8 files.** `_assemble_judge_injected_diff` and the EXECUTE JUDGE `git diff` capture stdout as bytes and decode with `errors='replace'`. Binary paths (PNG and other git-or-magic binaries) become a one-line stub (`Binary file <path> added|modified|deleted (<n> bytes)`); text hunks including latin-1 CSS stay in the prompt. Does not pass `git diff --text` / `-a`. Pass/revert routing is unchanged. Pinned by `tests/test_micro/test_judge.py::TestJudgeInjectedDiffBinarySafe`. ([#186](https://github.com/wernerbisschoff/deviatdd/issues/186))

- **JUDGE `COMPLIANCE_VIOLATION` whose only body is a `REFACTOR NOTE:` no longer reverts GREEN.** After a green suite, `_verdict_is_clean_pass` / `_feedback_is_refactor_only` treat `train_feedback` that is a `REFACTOR NOTE:` (optional `COMPLIANCE_PASS` preamble) with no structured Test Integrity failure as a clean pass — even when `verdict` is `COMPLIANCE_VIOLATION` and `next_action` is `revert_green`. The runner coerces to `continue_refactor` (or `skip_refactor` with `--no-refactor`) and keeps the GREEN commit. Unused imports, compiler warnings, and style stay REFACTOR's domain (`REFACTOR NOTE:` + `COMPLIANCE_PASS` + `continue_refactor`, never `COMPLIANCE_VIOLATION`). Real compliance / Test Integrity failures still `revert_green` / `revert_red`. GREEN TEST_FAILURE remap is unchanged. GH-158 `COMPLIANCE_PASS` + `REFACTOR NOTE` still continues.

- **JUDGE no longer rewrites a clean `COMPLIANCE_PASS` to `revert_green` when evidence quotes fail the substring gate (GH-185).** `_rewrite_unmatched_tdd_pass` returns the agent's forward action unchanged on a pass (`continue_refactor` if declared, else the GH-158 default to `continue_refactor` / `skip_refactor` when `--no-refactor`). It does not log `JUDGE_EVIDENCE_REJECTED`. A `REFACTOR NOTE` stays advice for REFACTOR. `COMPLIANCE_VIOLATION` still uses `revert_green` / `revert_red` as declared. Pinned by `tests/test_micro/test_judge_pass_unmatched_quotes.py`. ([#185](https://github.com/wernerbisschoff/deviatdd/issues/185))

- **`pi -p` TDD phases no longer die at 900s of stdout silence.** Print mode buffers all stdout until exit, so a healthy GREEN that finished at ~905s with a valid PASS was killed with `STALL_DETECTED` five seconds early. Silence stall and the 0 B/s smart-stall gate now skip a still-running `pi -p` / `omp -p` child; the wall-clock deadline still applies. Streaming backends still stall-kill. Default `STREAM_STALL_TIMEOUT_SECONDS` stays 900. ([#166](https://github.com/wernerbisschoff/deviatdd/issues/166))

- **JUDGE `revert_red` with structured `violations` (no `train_feedback`) now reaches the retry RED.** `_judge_feedback_from_manifest` already normalizes `violations` for `JUDGE_REJECTED`; that same payload is persisted as `**Judge Feedback**` after the reset and stays on `session.train_feedback`. Escalate no longer replaces it with `previous cycle failed because test defect` — the generic note is the fallback only when the payload is empty (a GREEN pytest dump is still wiped). If `_escalate_to_new_red` runs after `_apply_judge_verdict` already reverted, it does not reset again and drop the feedback commit. ([#170](https://github.com/wernerbisschoff/deviatdd/issues/170))

- **`revert_green` no longer resets to a stale RED SHA after a commit-train rebase (GH-168).** A rebase that rewrites RED (`7944a8a` → `de72f6c`) now remaps `session.red_commit_sha` and `judge_red_commit_sha` via `_refresh_session_commit_anchors` (exact subject-match on `git log HEAD`). `_red_anchor_kind` distinguishes a rewritten RED (remap, then reset) from an already-reverted session (HEAD was reset behind the stored SHA, or a feedback commit sits beside the discarded object). `revert_green` still refuses (`ROLLBACK_STALE_RED_SHA`) when the stored SHA is not an ancestor of HEAD and no rewritten RED can be found. `revert_red` remaps a rewritten RED to the current-train parent and no-ops a second `revert_red` instead of raising. `_execute_rollback` refuses a non-ancestor `boundary_sha` (`ROLLBACK_STALE_BOUNDARY`). `revert_green` keeps the current RED and unrelated commits that precede GREEN. Pinned by `tests/test_micro/test_rebase_red_sha.py`. ([#168](https://github.com/wernerbisschoff/deviatdd/issues/168))

- **Malformed JUDGE `COMPLIANCE_PASS` no longer reverts a valid GREEN (GH-167).** String `evidence` items recover as `parse_errors` and emptied `evidence`; that is a JUDGE execution failure (`JUDGE_MANIFEST_INVALID`), not a compliance rejection. Auto `_run_judge_phase` / `_apply_judge_verdict` and `deviate judge post` validate the full handover (YAML parse + `EvidenceItem` shape + `parse_errors`) before any revert or Judge Feedback write. Auto retries JUDGE on the same GREEN tree (cap 3) then stops with `JUDGE_MANIFEST_INVALID`; `judge post` refuses non-zero. `revert_green` still applies after a valid `COMPLIANCE_VIOLATION` or a valid PASS whose citations fail the evidence gate. JUDGE examples now show `ac: "AC-PLAN-001"` evidence objects (not strings; not `AO-*` / bare `AC-NN`). ([#167](https://github.com/wernerbisschoff/deviatdd/issues/167))

- **TDD GREEN budget now runs TRAIN 3/3 as a real GREEN, then escalates.** `green_attempts` increments at the start of each `_run_green_phase` (including the first) so three GREEN phase runs happen before `green_budget_exhausted`. `_train_green_or_escalate` no longer increments — incrementing there burned the last slot on escalate after two `revert_green` TEST_FAILURE cycles. `revert_red` / `test_defect` still escalate immediately; `_MAX_GREEN_ATTEMPTS` stays 3; `TRAIN_EXHAUSTED` still prints only after three RED escalates.

- **Escalate pre-RED walk no longer lands on a stacked docs-feedback SHA.** `_resolve_pre_red_sha` reuses `_resolve_judge_diff_base` to walk `docs(...): add judge feedback for retry` commits to the real RED-phase failing-test SHA, then returns that RED commit's parent. `PRE_RED_AMBIGUOUS` only when that true pre-RED parent cannot be resolved. `revert_green` still resets to the TRAIN boundary (feedback or RED), not pre-RED.

- **JUDGE `COMPLIANCE_PASS` + `REFACTOR NOTE` proceeds to REFACTOR instead of rejecting.** A clean pass that also emits a `REFACTOR NOTE:` (or leftover `next_action: revert_red` / legacy `revert_to_red`) no longer sets `JUDGE_REJECTED` or `revert_red` / `revert_green`. The runner defaults to `continue_refactor` (or `skip_refactor` when `--no-refactor`), injects the note into the REFACTOR `{train_feedback}` placeholder, and leaves GH-149 Test Integrity `revert_red` unchanged. ([#158](https://github.com/wernerbisschoff/deviatdd/issues/158))

- RED/GREEN/REFACTOR `pre` JSON, auto prompts, and the runner share one verification resolver: when mise is present, `test_command` is the resolved `mise test` / `mise unit` / `mise integ` / `mise exec -- …` string (plus the allowlisted task names that exist), and `_run_test_cmd` executes that same command after optional `mise doctor` preflight. ([#156](https://github.com/wernerbisschoff/deviatdd/issues/156))

- **RED now consumes persisted Judge Feedback the same way GREEN does.** Auto RED (`_run_red_phase`) falls back to the task's persisted `**Judge Feedback**` bullets from `tasks.md` as a `<persisted_judge_feedback>` block when session `train_feedback` is empty — previously only GREEN had this fallback, so a JUDGE `revert_red` correction was silently dropped when RED re-ran in a fresh session. The RED prompt gains a `<step id="feedback_ingestion">` documenting the same precedence GREEN uses (session `train_feedback` wins; persisted bullets are stale history) and binding-feedback language (each bullet is a mandatory correction). `deviate red pre` now emits `task_entry` (this task's `tasks.md` card, mirroring `green_pre`) so the manual `/deviate-red` slash command — which never receives placeholder substitution — can surface the same correction history. Pinned by `tests/test_micro/test_red.py::TestAutoRedPersistedFeedback` and `tests/test_meso/test_auto_prompt_templates.py::test_manual_red_routes_feedback_through_pre_contract`.
- **JUDGE revert routes renamed by blast radius: `revert_to_red` → `revert_green`, `revert_before` → `revert_red`.** `revert_green` discards GREEN and keeps RED; `revert_red` discards RED and GREEN. The old destination-named `revert_to_red` read as "revert RED too", so JUDGE agents misrouted rejections. The auto JUDGE prompt advertises only the new names; `_coerce_judge_action` and `SessionState.load` normalize the legacy names so pre-rename manifests and persisted `pending_judge_action` route identically. Forward routes (`continue_refactor` / `skip_refactor` / `proceed_to_refactor_no_diff`) are unchanged. Specs: `specs/DeviaTDD-api.md`, `specs/DeviaTDD-architecture.md`, `specs/_product/guildwright-current-system.md`. Pinned by `tests/test_micro/test_judge_action_rename.py`.
